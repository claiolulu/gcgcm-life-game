# 人生护照 · GCGCM 活动打卡护照

> 开发交接与当前实现请先读 [PROJECT_MEMORY.md](PROJECT_MEMORY.md)；Claude Code 的项目规则在 [CLAUDE.md](CLAUDE.md)。代码是事实来源，本文只讲怎么跑、怎么用、为什么这么设计。

格拉斯哥华人教会（GCGCM）的长期活动打卡护照。每个人领一本电子护照，教会的每一场活动是护照里的一张签证页：扫活动报名码报名，活动当天同工扫护照码盖章，护照上就留下「来过」的记录。

- **参与者端**：一本可翻页的电子护照（封面 → 欢迎 → 导航 → 资料页 → 每场活动的签证页 → 结语），外加排行榜、使用说明两个浮层。可以改个人资料和护照配色、给活动投稿文字和照片、开启活动通知、把护照添加到手机桌面。
- **同工端**：扫护照码（或输编号）找到人，一键给当前活动盖章。**断网也能盖章**，恢复网络后自动上传，不重复、不丢失。
- **总控台**：活动清单（搜索 / 筛选 / 排序 / 拖动调整装订顺序）、每场活动的详情页与画布编辑器、报名名单、通知推送、用户与标签管理、使用情况统计、导出与备份。

## 一、快速开始（本地）

```bash
npm run install:all
```

```bash
npm run build
```

```bash
npm start
```

打开 http://localhost:3000 ，同工端在 `/staff`。

`npm start` 走 `scripts/start-local-server.sh`：数据目录固定为项目的 `server/data/`，并且**拒绝在找不到已有数据库时启动**——防的是目录写错、悄悄开出一个空库。第一次在新机器上跑（还没有库）用开发模式，或者先放一份备份进 `server/data/game.db`。

开发模式下前后端分开跑（前端热更新）：

```bash
npm run dev:server
```

```bash
npm run dev:web
```

本地开发的兜底 PIN 见 `server/src/db.js` 的 `seedSettings()`，只在非生产环境生效。**生产环境必须用环境变量 `STAFF_PIN` / `ADMIN_PIN` 指定**（环境变量优先于数据库里存的值）；没提供时会随机生成并打印在启动日志里。这个仓库是公开的，真实 PIN 不要写进任何文件。

## 二、部署（公网 HTTPS）

**必须用 HTTPS。** 浏览器只在安全上下文下才允许摄像头扫码、注册 Service Worker 和推送通知。

**数据全在 `MLG_DATA_DIR` 这一个目录里**：`game.db`（SQLite，WAL 模式）、`uploads/`（上传的活动配图和投稿照片）、`backups/`。部署时整个目录必须挂持久卷，迁移时也要整个带走——推送密钥存在数据库的 settings 表里，换库会让所有人的通知订阅失效。

### 当前线上：本机 + Cloudflare 具名隧道

`game.claiolulu.com`（参与者）和 `staff.claiolulu.com`（同工，首页跳到 `/staff`）都由本机 3000 端口的服务提供，经 Cloudflare 具名隧道 `gcgcm-life-game` 暴露。服务用 `npm start` 启动，隧道单独运行：

```bash
cloudflared tunnel run gcgcm-life-game
```

服务和隧道要各自独立启动，不能挂在同一个父进程下，否则重启服务时会把隧道一起带走。凭据在 `~/.cloudflared/`，不在仓库里；换机器要带过去或重新 `cloudflared tunnel login`。

代价是**这台电脑就是服务器**：休眠、合盖、断网都会让站点断开，开机也不会自动恢复。

### 云端：Fly.io

仓库里的 `Dockerfile` 和 `fly.toml` 已配好（Node 22、`/data` 持久卷、监听 3000、健康检查 `/healthz`、不休眠）。首次部署步骤写在 `fly.toml` 顶部注释里；上线前用 `fly secrets set` 设置两个 PIN。**不要用 `fly launch` 重新生成 `fly.toml`**，它会把端口改成 8080。

### 部署后检查

1. `/staff` 用管理员 PIN 登录，总控台能看到活动清单和用户。
2. 手机打开首页，领一本护照，确认护照码能显示。
3. 另一台手机用同工 PIN 登录，扫这个护照码给某场活动盖章，护照上立刻出现章。
4. **开飞行模式再盖一次章**，顶部显示离线待上传，关掉飞行模式后自动上传。

## 三、使用

### 参与者

- **领护照**：首页填名字、捏头像、设 4 位密码。记住编号和密码，换手机时用它们找回同一本护照（连错 5 次锁 60 秒）。同名会提醒，避免同一个人领两本。
- **报名**：扫活动海报或朋友分享的报名码进入报名页（`/join/<活动id>`）。还没有护照的先领一本，领完自动回来报名。只有「还没到」的活动能报名。
- **签证页**：每场活动至少一张信息页，还可以有照片页、总结页。页上的「报名二维码」点开能分享给朋友；活动进入「进行中」或「已办完」后自动隐藏。页顶「上传」可以把文字或照片交给同工。
- **现场**：打开护照，出示资料页上的护照码给同工扫，盖完这一场就记为「已参加」。扫不出来就报编号。
- **通知**：点护照顶部的铃铛开启。安卓 Chrome 直接开；iPhone 必须先把网页「添加到主屏幕」、从桌面图标打开。第一次看完新手引导时会主动问一次。点活动通知会直接翻到那场活动的签证页。
- **个性化**：资料页右上角「✎ 自定义」改配色和资料。配色会应用到参与者端所有页面、弹窗和提示条。

### 同工

登录 `/staff`，选择负责的活动，扫护照码或输入编号盖章。每个人每场活动只能盖一次章（数据库唯一索引保证）。花名册缓存在本机，断网照常盖章，联网后自动上传。

### 管理员（总控台 `/staff/admin`）

- **活动清单**：搜索、按状态和可见范围筛选、按日期 / 报名人数 / 盖章人数 / 名称排序；「护照顺序」且未筛选时可以拖动调整装订顺序。「进行中」同时只能有一场。活动删光就是空清单，不会再回填出厂示例活动。
- **活动详情页**：基本信息、可见范围（所有人 / 报名可见 / 指定标签）、配图、页面链接、报名名单和到场情况、通知推送（选发给全部人、已报名、已参加或指定标签）。自动保存；手动保存后会问要不要发通知。
- **画布编辑器**：签证页上的每样东西都是可拖动、缩放、旋转、删除的块（横框、栏目、活动名、备注、配图、图库、链接、图标、文字、报名二维码）。编辑器和真护照用同一个渲染组件、同一套单位（位置是页面百分比，字号是页高 `cqh`），所见即所得。页眉、水印、护照码、章和底部机读区是固定模板，不是块。
- **用户**：搜索、改角色、挂标签（一个人可以挂多个）、重置密码、查看报名与参加记录、删除（会先备份）。
- **使用情况**：每天活跃人数、功能使用、活动转化。原始记录保留 180 天，不记 IP 和填写内容。

## 四、断网了怎么办

系统按「网一定会不好」来设计：

| 情况 | 会发生什么 |
|---|---|
| 参与者手机断网 | 护照和护照码照常显示，顶部提示离线。恢复网络自动更新。 |
| 同工手机断网 | 扫码、查人、盖章照常（花名册在本地），顶部显示待上传条数，联网自动上传。 |
| 服务器重启 | 各手机没传完的操作自动重试，不会丢。 |
| 同一操作重复上传 | 服务端按操作 ID 去重，重试多少次都只算一次。 |
| 两台设备同时给同一人同一场盖章 | 只有先到的生效，后到的显示冲突提示。 |
| 后台删了人或改了活动 | 各设备靠「数据纪元」发现本地花名册作废，下次同步整份重拉。 |

**前提：每部手机至少成功打开过一次页面**，之后断网才有缓存可用。

## 五、技术说明

```
参与者手机 (React PWA)         同工手机 (React PWA)
  缓存自己的护照                 缓存花名册 + 离线操作队列
        │                              │
        └──────── Socket.IO ───────────┘
                     │
          Node + Express + SQLite(WAL)
              仅追加的事件日志
```

**分数不是可被覆盖的字段，而是事件求和。** 多设备离线同步后自然收敛（加法可交换），重试不会重复记（操作 ID 做主键去重），每一笔都能追溯是谁、几点记的。

| 位置 | 内容 |
|---|---|
| [server/src/schema.sql](server/src/schema.sql) | 建表权威，`db.js` 启动时直接执行 |
| [server/src/db.js](server/src/db.js) | 迁移、SQL 语句、设置、备份 |
| [server/src/config.js](server/src/config.js) | 品牌文字、新库的出厂示例活动、默认配色、签证页栏目来源 |
| [server/src/game.js](server/src/game.js) | 可见范围、参与者状态、花名册、排行榜、盖章操作 |
| [server/src/index.js](server/src/index.js) | HTTP 接口与实时广播 |
| [server/src/push.js](server/src/push.js) · [usage.js](server/src/usage.js) | 通知推送、使用情况统计 |
| [web/src/lib/staff.js](web/src/lib/staff.js) | 同工端离线队列引擎 |
| [web/src/pages/book/PassportBookView.jsx](web/src/pages/book/PassportBookView.jsx) | 护照册视觉层，由设计稿机械转换而来，**不要手改内联样式** |
| [web/src/pages/book/bookVals.js](web/src/pages/book/bookVals.js) | 把实时数据喂给视觉层 |
| [web/src/pages/book/VisaBlocks.jsx](web/src/pages/book/VisaBlocks.jsx) | 签证页块渲染（编辑器与护照共用） |

**数据库迁移**：`db.js` 的 `rebuildIfLegacy()` 负责把迎新游戏时代的老库升级到当前结构（去掉旧列、删旧记录、先整库备份，整个过程在一个事务里）。`server/test-migrate.mjs` 专门测它——迁移是跑一次就回不去的代码，平时又不跑，值得单独测。

**签证页栏目来源**：栏目条的内容来自固定文字、持照人信息（名字、姓、名、编号、护照号、联系方式、参加过几场）、这一场（活动名、英文名、类型、负责人、日期、签发机构、编号）、这一页（出席状态、报名状态）。加一个来源要动三处：`config.js` 的 `VISA_ROW_SOURCES`、`bookVals.js` 的 `blockData()`、`VisaBlocks.jsx` 的 `bindRow()`。

## 七、设计稿与水印

护照册的视觉层是从 Claude Design 的 `.dc.html` **机械转换**出来的。设计改版后：

```bash
cd design && python3 convert.py && cp PassportBookView.jsx ../web/src/pages/book/
```

字体（EB Garamond / Noto Serif SC / Courier Prime）自托管在 `web/public/fonts/`，按 unicode 子集按需加载，不进预缓存。

**地标水印**在 `web/public/wm/`，共 14 张，全部改走运行时缓存、不进预缓存（Service Worker 安装是原子的，弱网下装不完就没有离线能力）：

- 签证页按「活动 id + 页 id」从 14 张里稳定地挑一张（`web/src/lib/visaWatermark.js`），刷新、翻页、换手机都不变，画板预览和真护照一致。
- 欢迎、导航、资料页分别用大教堂、威灵顿、大学三张；封面和结语不放。
- 原有 11 张由 `design/wm/extract.py` 从宫格插画提取；后加的中央车站、人民宫、墓园三张由 `design/wm/generated-to-watermark.py` 转换。新增地标只需把图放进 `web/public/wm/` 并加进 `visaWatermark.js` 的清单，不用改活动配置。

## 八、常见问题

**扫不出护照码？** 屏幕亮度调到最高；还不行就报编号，同工端「输码」永远可用，输 `7` 或 `07` 都能找到。

**忘了密码？（别让他重新领护照）** 管理员在总控台用户详情里重置密码，告诉他新密码后用编号找回。重新领护照会多出一个空号，参加记录还留在旧号上。

**换了手机 / 清了缓存？** 首页点「已经有护照？用编号找回」，输入编号和密码。

**点了通知还是打开报名页？** 该活动在他的护照里不可见（比如按标签发给了全部人），或者这台手机没登录——这两种情况会退回报名页，属于预期行为。

**摄像头打不开？** 确认访问的是 `https://` 地址。iOS 在 http 下不给摄像头权限。
