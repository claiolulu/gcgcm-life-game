# Mini Life Game · 人生护照系统

GCGCM 迎新大型互动游戏的电子护照系统，替代纸质护照与人工计分。

- **选手端**：一本可翻页的电子护照册（封面 → 欢迎 → 导航 → 资料页 → 八张签证页 → 恩典站 → 结语），外加实时排行与玩法两个浮层。视觉由 Claude Design 的 `Life Passport v5 Classic` 设计稿 1:1 移植，数据实时同步。**全程只读**，写不进任何东西。
- **工作人员端**：扫码（或直接输编号）找到选手，一键记分、抽人生盲盒、收 Help Token。**断网也能正常记分**，恢复网络后自动上传，不重复、不丢失。
- **总控台**：一份活动清单（点进去是这一场的全部）、护照与签证页模版、实时花名册、导出 CSV。

## 一、快速开始（本地）

```bash
npm run install:all
```

```bash
npm run build
```

```bash
npm start
```

打开 http://localhost:3000 。本地开发的默认 PIN：工作人员 `2026`，管理员 `stm2026`。

**这两个默认值只在开发环境生效。** 生产环境（`NODE_ENV=production`，Dockerfile 里已设）如果没有提供 `STAFF_PIN` / `ADMIN_PIN`，会随机生成一组并打印到启动日志里（`fly logs` 能看到）——因为这个仓库是公开的，写死默认值等于把总控台的钥匙贴在门上。正式部署请直接 `fly secrets set` 指定。

开发模式下前后端分开跑（前端热更新）：

```bash
npm run dev:server
```

```bash
npm run dev:web
```

灌一批演示数据（10 位选手，含各种状态）：

```bash
npm run seed
```

库里已经有人时它不会动，要重新灌加 `-- --force`。跑完会打出一张对照表：每个人的编号、4 位密码、身份、分数，方便直接以某位选手的身份打开护照。

数据是特意配出来的，覆盖需要肉眼验证的各种状态：有并列名次、有 Solo/Duo/Trio、有人抽过人生盲盒（含积分减半）、有人用掉了 Help Token、有人身上挂着「下一关最多 1 分」，还留了 **2 个未分配身份的人**，这样总控台的「一键分配」才有活干。

跑测试：

```bash
npm test
```

测试用固定的操作 ID，所以会先清库；跑完会自动重新灌一次种子数据，库里始终是那 10 个人。

## 二、部署（公网 HTTPS）

**必须用 HTTPS。** 浏览器只在安全上下文下才允许调用摄像头和注册 Service Worker——也就是说，用 `http://` 的局域网地址部署，工作人员的 iPhone 扫不了码，所有人的离线缓存也会失效。

**数据存在 SQLite 单文件里，部署时必须挂持久卷。** 用没有磁盘的免费实例，一次重启或重新部署就会把全场积分清空。

### 方案 A：Fly.io（推荐）

```bash
fly auth login
```

```bash
fly apps create gcgcm-life-game
```

```bash
fly volumes create mlg_data --size 1 --region lhr --yes
```

```bash
fly deploy
```

部署完改 PIN（随时可改，改完自动重启就生效）：

```bash
fly secrets set STAFF_PIN=你们的PIN ADMIN_PIN=只有负责人知道的PIN
```

PIN 的取值是**环境变量优先、其次才是数据库里存的值**。这一点很关键：PIN 在首次启动时会被写进数据库，如果不让环境变量优先，`fly secrets set` 会完全不起作用 —— 你改了 secret，却发现旧 PIN 照样能登录、新 PIN 进不去。

`fly.toml` 已经配好持久卷、强制 HTTPS、关闭自动休眠。区域选了 `lhr`（伦敦），离格拉斯哥最近。

### 方案 B：Render.com

推 `render.yaml` 即可，但**必须选 starter 付费档**（约 $7/月，活动结束后删掉）。免费档文件系统是临时的且会休眠，不能用。PIN 在 Render 后台的环境变量里填。

### 方案 C：Cloudflare Tunnel（备用 / 测试用）

**固定域名版（推荐，已配好）**：本项目已经建好 named tunnel `gcgcm-life-game`，绑在 **https://game.claiolulu.com**。直接 `./scripts/tunnel.sh` 就用这个地址，重启进程、重启电脑、换网络都不变。

脚本靠三个条件判断走固定域名还是随机地址：`~/.cloudflared/cert.pem` 存在、`scripts/.tunnel-host` 里有域名、且该 named tunnel 确实存在。任一不满足就退回随机地址。

换一台机器跑要先把授权带过去 —— 凭据在 `~/.cloudflared/`（`cert.pem` 和 `<隧道ID>.json`），拷过去，或者在那台机器上重新 `cloudflared tunnel login`。

从零配一个新域名：域名 DNS 托管到 Cloudflare（注册商那边的 nameserver 换成 Cloudflare 给的两个，**只留这两个**，混着原来的会一直激活不了）→ `cloudflared tunnel login` → `cloudflared tunnel create <名字>` → `cloudflared tunnel route dns <名字> <域名>` → 把域名写进 `scripts/.tunnel-host`。


云端还没落实，或者当天云端出意外要马上切备份：

```bash
./scripts/tunnel.sh
```

服务跑在本机，隧道给一个 `https://xxx.trycloudflare.com` 的公网地址，**不需要 Cloudflare 账号**，脚本会把地址连同二维码一起打在终端上，Reception 直接举着屏幕让人扫。前提是装了 `cloudflared`（`brew install cloudflared`），没装脚本会提示。

隧道自带证书，所以摄像头扫码和 Service Worker 都正常 —— 这两样都要求安全上下文，局域网 `http://` 地址是不行的。

**地址每次重开都会变，但不影响已经发出去的护照**：选手护照上的二维码编的是 `MLG:01` 这样的编号，不是网址。

实测过（2026-08-31）：HTTPS 有效、socket.io 实时同步通、Service Worker 注册成功、四个缓存（预缓存 / 接口 / 水印 / 字体）全部建立、11 张水印预取入缓存；把服务和隧道一起杀掉后刷新，护照照常打开、水印还在、数据完整，状态灯转黄显示 RECONNECTING。

代价是**那台笔记本就是唯一的服务器**：不能休眠、不能断网，盖上盖子全场就断。正式活动还是建议用 Fly，这条留作备份。

### 部署后必做

1. 打开 `/staff`，用管理员 PIN 登录总控台，确认状态是「入场 / 报名中」。
2. 手机上打开首页，走一遍报名流程，确认能生成护照和二维码。
3. 用另一台手机的工作人员端扫这个二维码，确认能记分。
4. **把飞行模式打开再记一次分**，确认顶部出现「已离线记录 N 条」，关掉飞行模式后自动上传。
5. 生成入口二维码（指向部署好的域名首页）打印出来，Reception 摆两张。

## 三、现场操作手册

### 入场阶段（约 15 分钟）

- Reception（嘉南、彤彤）引导新生扫入口二维码 → 填名字 → 捏头像 → 生成护照。
- 第一次打开护照会**自动走一遍新手引导**：把页眉上的排行榜、队伍、恩典站、玩法四个按钮逐个高亮出来，配一句说明，点「下一个」直到走完（也可以跳过）。之后随时点页眉的 `?` 重看。
- 护照的第三页（导航页）是活动简介，讲清楚这 60 分钟怎么玩。
- 头像有 10 种发型 × 10 顶帽子 × 5 副眼镜 × 5 件饰品，**三个配饰槽位可以同时戴**，背景还能选 10 座城市的风景（格拉斯哥、爱丁堡、伦敦、巴黎、纽约、东京、悉尼、上海、罗马、旧金山），也可以点「🎲 随机」直接抽一个。头像会铺满护照资料页的证件照框。
- 提醒大家：**把这个页面留着别关**，加到主屏幕更好。
- 二维码下面那个号（`#01 号`）就是他的编号，扫不出来的时候报这个号给工作人员。
- **忘了编号**：在「用编号找回护照」里输名字的两个字就能查，点一下结果就填进编号栏。查询只回编号和姓名，不回密码 —— 这两样排行榜上本来就是公开的，所以不比现状多暴露什么。按 IP 限流，一分钟 20 次，防的是有人拿它当花名册导出。
- **密码不好记**：同一个弹层里点「顺便把密码改成好记的」，输原密码 + 新密码，改完直接进护照。要知道原密码才能改，和找回护照共用同一个防爆破计数（连错 5 次锁 60 秒）。
- **原密码也忘了**：找 Reception，总控台可以重置成 3927。别让人重新报名 —— 会多出一个空号，分数也对不上。
- 报名时会拿到一个 4 位密码，只有换手机或清了缓存要找回护照时才用得上。护照页「我的登录信息」里随时能看到，建议截图存着。

### 游戏开始

1. 总控台点「游戏进行中」——护照信息随即锁定，没人能再改名换头像。状态一离开「入场」，**报名开关会自动关掉**；但中途还有人来的话，同工在总控台手动打开「开放报名」就能让他自助报名，不必切回入场阶段。报名只看这一个开关，不再额外卡游戏阶段。
2. 总控台的「身份分配 / 组队」有三个入口，按需要选：
   - **一键分配这 N 人**（最常用）：只给还没有身份的人分配，**已经找到队友的人完全不动**。陆续有人报名时随时点。
   - **手动勾选分配**：勾几个人 → 选 SOLO / DUO / TRIO，同队自动拿到同一个颜色 + 符号，也能把人退回未分配。
     身份和人数**必须严格对应**（Solo 1 人、Duo 2 人、Trio 3 人），人数不对时按钮直接禁用并写明「还差 N 人 / 多了 N 人」，服务端也会拒绝。
     把某人从原队伍抽走（或退回未分配）时，**原队剩下的人会自动降级**：三人队变两人 → Duo，两人队变一人 → Solo 并脱离队伍。
     不这么做的话场上会留下「只有两个人的 Trio」，而 Trio 的评分要求是三人各答一题，工作人员当场没法判。
   - **全部重新洗牌**：把所有人打散重来，开场前彩排完再用。
   分配后所有人的手机会**自动弹出「我的队伍」面板**：大号的颜色 + 符号徽记（举着手机互相对暗号），下面直接列出队友的头像、名字和编号，还有建议首站。
   护照封面**轻触任意位置即可翻开**；内页点左右边缘（各 25%）前后翻页，也可以用方向键。
   面板收起后，护照册**每一页的左上角、排行榜奖杯图标旁边**都常驻一枚队伍徽记（用队伍色显示符号和颜色名，比如红色的「★赤」），随时点开再看。还没抽身份时显示中性的 🪪。Solo 不显示队友列表，改为说明他的优势关。
3. 系统给每组分配了不同的首站，身份卡上会写「建议先去 XX」，人群自然分流。

### 各站记分

工作人员在自己手机上登录 `/staff`，选好自己负责的站，之后每次扫码都会直接跳到那个站的记分界面。右上角的 `⋯` 里可以**中途换站点**，也可以**退出登录**（还有记分没上传时会先拦一道，避免记录丢掉）。

- 三个大按钮：**3 勉强 / 6 正常 / 9 出色**，另有「0 分挑战失败」和「1 分安慰分」。记分后选手护照对应的签证页上会盖上相应颜色的印章。
- **每站只有一次机会**。已经记过分的关卡会直接显示是谁、什么时候记的，防止重复给分。
- 选手身上挂着的状态分两类，界面上长得不一样：
  - **红框「要你核实」**——比如「下一关必须邀请一位还不认识的人」。这类不核实就等于卡白抽了，所以配了明确指令（「记分前先确认：他身边这位是刚认识的吗？没带人就先别记分」）。花名册上也会标「有附加条件」，点进去之前就看得到。
  - **黄框**——比如「重感冒：下一关最多 1 分」。系统自动封顶，同工照常按表现记分即可。
- 界面会显示选手当前名次，方便执行「分数高者优先排队」。

### 人生盲盒站（场地正中央）

选手总分跨过红线（默认 15 / 30 / 50）时，他自己的护照会弹出红色警告，工作人员扫码时也会看到「这位选手欠 N 次人生盲盒」。

在记分页点「🎲 人生盲盒」→ 让选手自己点「抽一张人生卡牌」→ 翻牌动画 → 确认应用。加减分和状态效果全自动结算。

**结算完选手自己的手机上会弹出这张卡**：类别、插画、卡面故事，以及最要紧的「结果」—— 效果描述加实际加扣了几分。以前只有同工那边看得到抽了什么，选手只知道分数变了，为什么变、下一关有没有附带限制全靠现场口头转述，人一多根本听不清。

15 张卡各有一幅小插画（`web/src/components/CardArt.jsx`），全是内联 SVG，没有任何需要下载的资源。

### 恩典站

选手交出 Help Token，工作人员点「✝️ 恩典站」，二选一（提示/NPC 协助 或 免费重来一次），确认后记录。界面上写着要念给他听的那句话。

### 结束

1. 总控台点「已结束」。
2. 颁奖区出现，逐个指定「最高积分奖」「The Connector」「The Creative」等。
3. 选手打开「徽章」页，点「生成分享图」，长按保存，可发朋友圈。
4. 总控台导出 CSV 存档。

### ⚠️ 容量：八关跑不完

按 50 人（约 30 组）、实际闯关 33 分钟（60 分钟扣掉入场 15、开场分配 5、颁奖 7）估算：

| 关卡 | 单组耗时 | 这段时间能接待 | 覆盖率 |
|---|---|---|---|
| 🕳 摸黑套圈 | 1.5 min | 22 组 | 73% |
| 🔀 人生选择 | 1.5 min | 22 组 | 73% |
| 🎵 音乐之声 | 1.7 min | 19 组 | 63% |
| 🤫 寂静图书馆 | 1.8 min | 18 组 | 60% |
| 🇬🇧 英伦百事通 | 1.8 min | 18 组 | 60% |
| 🧠 记忆观察 | 3.0 min | 11 组 | 37% |
| 🎤 灵魂拷问 | 3.0 min | 11 组 | 37% |
| 📸 定格瞬间 | 4.0 min | 8 组 | 27% |

**满分 72 是按八关全通设计的，现场达不到。** 把排队和走动算进去模拟一遍，每组实际只跑得完 **2–3 关**。最堵的是定格瞬间：4 分钟一组（Solo 还得现场拉路人配合），整场只接待得下 8 组，30 组里 22 组根本轮不上。

这是活动设计的取舍，代码解决不了。三个方向：

1. **给慢关加并行席位** —— 定格瞬间摆两三套道具背景、记忆观察备两套物品，接待量直接翻倍。最有效。
2. **改计分口径** —— 别说「满分 72」，改成「完成任意 N 关」或按人均 3 关重新定档，免得所有人都觉得自己没玩完。
3. **砍关卡** —— 八关减到五六关，每关都跑得满。

耗时估算写在 `server/src/config.js` 每个关卡的 `minutes` 字段里，彩排一遍之后按实际改，排班算法会跟着变。总控台在游戏进行中会显示「容量体检」，可以当场按剩余时间重算。

### 关卡顺序（减少排队）

50 个人 8 个关卡，如果人人都从第一关开始，开场十分钟全堵在门口。所以每个人（准确说每一队）有自己的关卡顺序：

- **赛前签证页是空的**，只写「待公布」。写上具体关卡等于提前泄底，还会让人扎堆去自己看到的第一关。
- **点「游戏进行中」的那一刻**后台统一排。第一版是「起点轮换 + 互质步长」，把人均匀撒到 8 个关卡上，隐含假设是每关耗时相同。实际差三倍（1.5 分钟 vs 4 分钟），于是快关空着、慢关排长队。

  现在改成**按耗时排班**：把每个关卡当成一台机器、每组当成要依次经过所有机器的工件，在内存里模拟整场，贪心地让每组下一个去「最早能轮到它」的关卡（即 `max(这组空闲时间, 该关空闲时间)` 最小的那个）。这是列表调度（list scheduling）的经典做法，耗时差异被自然吸收。

  30 组 / 33 分钟的模拟对比：**完成关次 +63%，每完成一关的平均等待 −24%**。更要紧的是最少完成关数从 **0 变成 2** —— 旧算法下有的组一关都跑不完。
- **同队必须同路线**：Duo/Trio 是绑在一起行动的。编队变动后只修「队内不一致」的队，并以队里走得最远的人为准，不动其他人。
- **中途加入的人**（主持人临时切回「入场」放人进来）从**当前最空的关卡**切入。忙闲不是看完成数——完成得多既可能是人多也可能是流程快——而是数各人路线上「下一个还没盖章的关卡」，那才是此刻门口在等的人。每发一条重算一次，连着来两个人也会被分到不同的关。
- 切回「进行中」时**只补新人**，绝不重排已经在跑的人：把闯了三关的人的顺序打乱，他手上正在排的队就白排了。

总控台在游戏进行中会显示「📍 各关排队情况」。这个数据搭同步响应的顺风车下发（347 字节，只有 id 和两个数字，关卡名图标客户端本来就有），不额外发请求。

### 排行榜按队排

一队一行，不是一人一行：上层是队名和人数，下层是队员头像叠成一排、名字和各自的分数，右边是这一队的分。

**排名用人均分不是总分。** 总分排的话 Trio（三人，上限 216）永远压过 Solo（上限 72），没有可比性；队友本来就一起闯关，分数几乎一样，人均分就是这一队的水平。个人分仍然逐个显示，底部还有一处「按个人总分看」—— **最高积分奖判的是个人总分**，组队榜取代不了它。

**队名队员自己改**：护照页眉的队伍徽章 → 「我的队伍」→「改个队名」。任何一个队员改，全队同步，排行榜上立刻显示。最多 12 个字。没改过的显示按颜色生成的默认名（「赤队」）；Solo 和还没编队的人直接显示本人名字 —— 「赤队」只有一个人很怪。

组队榜搭 `/api/leaderboard` 同一个响应下发，没有额外请求。

## 四、断网了怎么办

系统就是按「网一定会不好」来设计的，现场基本不用管：

| 情况 | 会发生什么 |
|---|---|
| 选手手机断网 | 护照和二维码照常显示，顶部提示「离线模式」和数据的时间。恢复网络自动更新。 |
| 工作人员手机断网 | 扫码、查人、记分全部照常（花名册缓存在本地）。顶部变红显示「已离线记录 N 条」，恢复网络自动上传。 |
| 服务器重启 | 各手机上没传完的记分会自动重试推上去，不会丢。 |
| 同一条记分重复上传 | 服务端按操作 ID 去重，重试一百次也只算一次。 |
| 两台设备同时给同一人记分 | 分数是事件求和，不会互相覆盖，最终结果一致。 |
| 两台设备抢同一个关卡 | 只有先到的生效，后到的会在对方手机上显示冲突提示。 |
| 后台重置了数据 | 各设备靠「数据纪元」发现自己手里的花名册作废，下次同步自动整份重拉，不会留下已被删除的幽灵选手。 |

顺带一提：**选手平时根本不需要登录**。报名之后令牌就存在浏览器里，打开就是自己的护照。编号 + 4 位密码只在换设备时用一次。

**唯一的硬性要求：每部手机在入场时必须成功打开过一次页面**，之后断网才有缓存可用。所以入场那 15 分钟一定要让大家先把页面打开。

真的全崩了：总控台导出的 CSV 里有全部人的编号、密码和当前分数，改用纸笔记分，赛后由管理员在总控台手动补录。

### 活动清单（总控台 🗓）

护照里一场活动一页签证。加、删、改、调序都在总控台，保存就生效 —— 服务端每次都现查活动表，不用重启，同工端和所有人手里的护照会一起变。

`config.js` 里的 `ACTIVITIES` 只是**首次启动的种子**，之后以库里那份为准（存在 `settings` 表的 `_activities` 下）。

- **id 建了就不能改**：盖过的章记在 `events.station_id` 里，id 是那条记录的锚。新建活动时自动生成（`act-<时间戳>`），界面上只显示不给编辑。
- **删之前会告诉你代价**：确认框写明「已经有 N 个人在这一场盖过章」。删掉之后护照里不再有这一页，那些记录还在库里但不会显示。
- **配图**：每场活动可以配一张照片，贴在签证页右上角。选完文件浏览器会先压到 1280px / JPEG（手机直出的四五兆图原样传上去，护照页要加载好几秒），存在 `server/data/uploads/`，文件名是内容哈希 —— 同一张图传几次只存一份，换图就是换地址，所以前端可以放心长缓存。上传完**还要点保存**才算数。

### 总控台的结构

打卡本里「一场活动」就是一切的中心 —— 护照上的一页、同工要盖的那个章、现在开不开放报名，全都长在它身上。所以总控台只留一份**索引**：

```
总控台
├─ 🗓 活动清单        ← 一行一场，点进去是这一场的全部
│   └─ 活动详情页 /staff/admin/a/<id>
│       ├─ 🎨 设计这一页 → 画布编辑器 /staff/admin/a/<id>/design
│       ├─ 🎯 这一场   还没到 / 进行中 / 已办完 · 报名开关
│       ├─ 📣 报名     报名码 + 谁报了 + 到没到场
│       ├─ 👥 已参加   谁盖了章、什么时候、谁盖的
│       ├─ 📝 基本信息 名字、日期、类型、负责人、说明
│       ├─ 🖼 配图
│       ├─ 🔗 页面链接
│       ├─ 🎫 这一页的版式
│       └─ 🗑 删掉这一场
├─ 🎫 签证页模版      ← 全局，跟随模版的活动一起变
├─ 🎨 护照模版        ← 全局
├─ ⚙️ 参数 / 💾 数据 / 👥 全部选手
```

**「进行中」同时只能有一场**（服务端强制）。把第二场设成进行中时，总控台会先问一句，然后把原来那场标成「已办完」。这一场的状态还决定两件事：同工扫码默认盖哪一场，以及护照信息锁不锁 —— 活动期间锁住（免得有人中途改名），两场之间可以改。

**报名开关只在「进行中」那一场里露出来。** 它是全场唯一的一个开关，放在正在办的那一场旁边，才知道自己开的是什么。

#### 迎新游戏的那些面板已经从总控台拿掉了

这条分支（`passport-checkin`）的总控台不再有：游戏状态、身份分配 / 组队、各关排队情况、容量体检、每组的关卡顺序、颁奖、人生盲盒红线、记分档位。它们是一晚上那场游戏的东西，一本用一年的打卡本用不上。游戏版仍然完整地留在 `main` 分支。

⚠️ **代价**：抽身份 / 编队的入口没了，所以护照资料页的「CLASS 身份」「TEAM 队伍」和恩典站那一页不会再被填上。服务端的接口（`/api/admin/draw`、`/api/admin/team`）还在，需要的话可以直接调，或者把那几页从护照里也去掉。

### 画布编辑器（新增活动 → 直接打开）

总控台「🗓 活动清单」右上角的 **＋ 新增活动** 建好之后进这一场的详情页 —— 名字、日期、负责人、签发机构是这一场的底子，版式是填完这些才谈得上的事。详情页右上角的「🎨 设计这一页」进画布。

**这一页上的每一样都是一个块**：VISA 横框、签发站那片栏目、活动名、备注、配图、页面链接、机读区，加上同工自己摆的字和图。每个块都能挪、能改大小、能转、能删。

- 横框：左边那个词、右边那两行字（「MINI LIFE GAME」）都能改
- 栏目：一栏一栏地加删改，标题自己写，内容选「数据来源」（固定文字 / 姓 / 名 / 编号 / 出席状态…），还能改列数
- 配图和图片：铺满或完整显示、圆角、旋转、透明度 —— 转着叠在栏目上是允许的
- 文字：字号、字体、颜色、对齐、加粗、行距
- 每个块都能挂超链接

**删光就是一张白页**，然后自己贴海报 —— 那是刻意允许的（空数组和「没设计过」在服务端是两件事）。「清空」「恢复默认」两个按钮，加上「＋ 加一个块」里能把删掉的内置块加回来。

留在块之外的只有四样，各有理由：

| 不是块 | 为什么 |
|---|---|
| 页眉那排按钮 | 那是 App 的导航（队伍、分数、恩典站），不是这一页的内容 |
| 地标水印 | 跟着地标走，在护照模版里统一调 |
| 右下角二维码 | 同工要扫它盖章，挪走了现场就乱 |
| 那个章 | 活动当天盖上去的，任何块都不该盖住它（所以它在块之上） |

**为什么能所见即所得**：块在编辑器里和在真护照上是同一个组件（`VisaBlocks.jsx` 的 `BlockBody`）、同一套单位（位置是百分比，字号是页高的 `cqh`），连**层叠位置**都一样 —— 编辑器把可拖的那层塞进 `VisaPageFrame` 的插槽里，和真页面同一个位置。

**默认版式**由 `bookVals.js` 的 `defaultBlocks()` 生成，坐标是照着原来那份写死的排版量出来的，所以没设计过的活动看起来和以前一模一样。全局的「🎫 签证页模版」现在的作用是**给默认版式当种子** —— 一场活动在编辑器里动过之后就存自己的 `blocks`，从此和模版无关。

**总控台整体是宽屏排版**（≥900px）：卡片排成网格（不是多栏 —— 多栏是「灌满一列再开下一列」，读起来是竖着的，而这些卡片彼此独立，横着读才对），概览和活动清单横跨整行，活动清单和花名册里的条目自己再排成几列。同工端的扫码页和选手页也跟着放宽了。

网格有一个坑：**行高按这一行最高的那张卡算，矮的填不回去**（那是 masonry，CSS 网格还做不到）。所以高矮差很多的卡片不能各占一格 —— 1440px 下第一版就是「护照模版 801 高，旁边两张 147 和 265，底下白掉六百多」。做法是把几张矮卡片用 `.cell-stack` 摞成**一个**网格单元：

- 总控台：护照模版 / (参数 + 数据) / 花名册 → 三栏 526·435·491，整页高从 2710 降到 1089
- 活动详情页：
  - **左** 这一场是什么 —— 基本信息、页面链接、配图合成一张卡，各自的小标题就是分隔
  - **中** 现在怎么样、怎么让人来 —— 这一场（状态 + 报名开关）、报名（二维码 + 名单）
  - **右** 谁来了 —— 已参加名单单独占一摞，人多了也有地方看，超过 68vh 自己滚
  - 右上角三个按钮：🎨 设计这一页 · 💾 保存 · 🗑 删除（红框）
  - **页面自动保存**：停手 1.2 秒存一次。这一页全是零碎的输入框，每改一处都要人记得按保存，迟早有人改完直接关掉。自动保存不吐提示（一页填下来能弹十几次），但**失败一定要说** —— 不吭声的话人以为存上了。保存按钮留着，给「想立刻落盘」和「自动保存失败过一次」用
  - 每一栏该填什么写在灰字提示里，不在框下面另起一行解释；说明改成可拉高的多行框
  - 日期旁边有个 📅，从日历里挑一天，写成 `13 SEP 2026` 塞回文字框。**文字框才是主的** —— 这一栏印在签证页的签发日期上，而查经是「每周三」、退修会是「待定」，换成纯日历控件这些就填不进去了。文字认得出日子就把日历预选到那天，认不出就不预选也不清空
  - 三摞 772·736·537，整页高 1283 降到 980

同时长列表（花名册）在宽屏下限高自滚，不然一张卡一千二百多像素高，真正要看的东西全被推到屏幕外；护照模版里那六个「印在护照上的字」折进 `<details>`，装好一次之后基本不会再动。

画布编辑器的**电脑上是左右两栏**（≥1000px）：纸钉在左边不动，属性面板自己滚 —— 摆东西时最不想要的就是「改个字号，纸滚出视野了」。手机上还是从上到下一条。活动详情页在宽屏下也会自动排成两到三列。

**快捷键**（只在宽屏提示，手机上那一行是纯占地方）：

| 键 | 干什么 |
|---|---|
| <kbd>Del</kbd> / <kbd>Backspace</kbd> | 删掉选中的块 |
| <kbd>←↑→↓</kbd> | 挪 0.5%，按住 <kbd>Shift</kbd> 挪 5%，按住 <kbd>Alt</kbd> 改大小 |
| <kbd>[</kbd> <kbd>]</kbd> | 往下 / 往上一层 |
| <kbd>⌘D</kbd> | 复制一个 |
| <kbd>⌘S</kbd> | 保存 |
| <kbd>Esc</kbd> | 取消选中（在输入框里则是失焦） |

在输入框里打字时除了 <kbd>Esc</kbd> 和 <kbd>⌘S</kbd> 一律放行 —— 不然写活动介绍打个 Delete 就把选中的块删了。方向键微调走的是「按当前值改」而不是「算好了塞进去」：连按两下时两次事件在同一帧里，后者两次都从同一个起点算，按两下只动一格，而按住方向键不放正是最常见的用法。

两点要知道：栏目里填的是示例值（真页面上每个人不一样）；页面比例按常见竖屏手机取 1.9:1 —— 横版页在竖屏手机上是整个舞台转 90°，所以页的宽高比等于手机屏的高宽比，本来就不是个定值，特别长或特别方的屏上会有出入。

### 报名（活动页 📣）

每场活动有自己的报名码。贴出去或投到屏幕上，扫了就是这一场的报名页（`/join/<id>`）：

- **已经有护照的** —— 一下就报上了
- **还没有的** —— 先领一本护照，领完自动回到这一页并把名报上（`?next=…&signup=…`）

不做「只留个名字」的轻报名：这套系统里「你是谁」就是那本护照，报名时另开一条只有名字的记录，活动当天同工要盖章的时候对不上人。

活动页上能看到**报了多少人、具体是谁**，以及每个人**到没到场**（报名和盖章是两回事 —— 报了 30 个来了 12 个，说明提醒没做到位，不是活动没人要）。

报名存在 `signups` 表，主键是 `(活动, 人)` —— 重复提交天然幂等，取消就是删掉那一行。名单带联系方式，所以只有管理员看得到；公开的活动接口只给名字、日期、说明和报名人数。

### 栏目条能绑什么

栏目条（签发站、控制号、姓、名……）每一条只有两件事：**印什么标题**（自己写），**内容从哪来**。来源按组分开，下拉里好找：

| 组 | 来源 |
|---|---|
| 自己填 | 固定文字 —— 所有人看到的都一样 |
| 持照人 | 名字、姓、名、编号、护照号、联系方式、身份、队伍、参加过几场 |
| 这一场 | 活动名、英文名、类型、负责人、日期、**签发机构**、**控制号** |
| 这一页 | 出席状态、盖章日期、报名状态 |

默认版式里**没有**「出席状态」那一栏 —— 来没来过，那个章已经说得很清楚了，再用一行字写一遍 ✓ 是重复。需要的话在画布编辑器里加回来，来源还在。

**签发机构**在活动详情页的基本信息里填，留空就用护照模版上那个（整本护照的签发方）。**控制号**印的是「签发机构 + 日期」——原来是「护照号/页码」，那是护照自己的编号，每一页都一样，印在签证页上没说出任何关于这一场的事。

除「固定文字」外都按人算 —— 姓名、编号、来没来过每个人不一样，让同工去填只会填错。加一个来源要动三处：`config.js` 的 `VISA_ROW_SOURCES` 加一行、`bookVals.js` 的 `blockData()` 加一个键、`VisaBlocks.jsx` 的 `bindRow()` 加一个 case，三处齐了才生效。

**「签证页模版」这个全局选项已经去掉了。** 每一场的版式在它自己的画布编辑器里排，默认版式是代码里的常量（`config.js` 的 `VISA_TEMPLATE` → `bookVals.js` 的 `defaultBlocks()`）。多留一个「模版」只会让人先去改模版、发现某一场没跟着变、再回来找原因。

### 页面链接（总控台 🔗）

每场活动最多挂 6 个链接，印成签证页上一排可点的小图标 —— 📷 活动相册、📝 报名表、📍 场地地图、💬 微信群。点一下在新标签打开。

图标点一下从调色板里挑（相册、报名表、地图、群、日程、诗歌、经文、视频、吃什么、怎么去、费用、票、文件、说明、常见问题、链接）—— 让人自己打 emoji，电脑上要按 ⌃⌘空格 翻半天，手机上要切输入法，而实际用到的翻来覆去就那十几个。挑的时候名字还空着就顺手代填（选 📷 多半就是要写「相册」），已经写了的不动。想用别的 emoji，调色板下面留了输入框。

地址只收 `http(s)`：这个值会变成页面上的 `<a href>`，收 `javascript:` 就是一条 XSS。用的是真的 `<a>` 而不是 `div + onClick`，翻页判断靠 `closest('a')` 认出「这一下不是翻页」，长按也才有「复制链接」。

### 护照模版（总控台 🎨）

改所有人手机上那本护照的样子，面板里带实时预览：

| 能改的 | 说明 |
|---|---|
| 四套预设 | 经典酒红 / 午夜深蓝 / 林地墨绿 / 牛皮纸，点一下整套换掉 |
| 主色 / 烫金 / 纸色 / 正文 / 盖章 | 五个取色器。设计稿里有三档金，只调最亮那一档，另外两档按比例算出来 |
| 水印浓度 | 每页底下那张地标图的浓度，上限 0.30（再浓会压住正文） |
| 印在护照上的字 | 封面大字 / 英文 / 签发机构 / 副题，签证横幅的中英文 |

实现上，设计稿里写死的色值在转换时被机械替换成 CSS 变量（`design/convert.py` 的调色板补丁，184 处），变量由 `bookVals.js` 的 `themeVarsOf()` 算好挂在护照册最外层。变量名一律带 `pp-` 前缀 —— App 自己的设计令牌里已经有 `--ink` / `--gold` / `--text`，同名重定义会把护照里所有用 App 样式类的元素一起染色。

**改完不用让人重新打开页面。** 服务端广播 `config`，各端收到就重拉配置、当场重绘，停在哪一页还是哪一页。

```bash
npm test
```

测试会**另起一个服务实例**：端口 3199、数据库在 `server/data-test/`，每次从空库开始。现场那份 `server/data/game.db` 完全不受影响。

以前测试直接打 `localhost:3000` 并且会调 `/api/admin/reset`，等于每跑一次测试就把正在用的数据清空一次 —— 彩排时报名的人就是这么没的。

要重置现场数据是另一件事，明确去做：总控台的「⚠️ 重置游戏数据」，或者 `npm run seed -- --force`（会先自动备份）。

## 六、技术架构

```
选手手机 (React PWA)          工作人员手机 (React PWA)
  缓存自己的护照                 缓存整份花名册 + 离线记分队列
        │                              │
        └──────── Socket.IO ───────────┘
                     │
          Node + Express + SQLite(WAL)
              仅追加的事件日志
```

**核心设计：分数不是一个可被覆盖的字段，而是一条条不可修改的事件求和得来的。**

这一个决定解决了三件事：多设备离线记分同步后能自动收敛（加法可交换）；重试不会重复加分（操作 ID 做主键去重）；任何一笔分数都能追溯到是谁、几点、因为什么记的。

- 倍率类卡牌（积分 ×2 / 减半）会在服务端用当时的权威总分**结算成一个加减法增量**再落库，这样事件流保持纯加法，收敛性不被破坏。
- 「每站一次机会」由数据库的部分唯一索引强制保证，不靠应用层自觉。
- 状态效果（如「下一关最多 1 分」）挂在选手身上，下次记分时自动生效并消除。
- 服务端每 60 秒自动导出一份 JSON 快照到数据目录，另有 CSV 和完整备份可随时下载。

## 七、设计稿更新了怎么办

护照册的视觉层是从 Claude Design 的 `.dc.html` **机械转换**出来的，不是手写的。设计改版后：

```bash
cd design && python3 convert.py && cp PassportBookView.jsx ../web/src/pages/book/
```

转换器负责把 `<sc-if>` / `<sc-for>` / `{{ }}` 变成 JSX，把内联 `style` 变成 style 对象，并把输入框设为只读。新增的数据字段要在 [bookVals.js](web/src/pages/book/bookVals.js) 里补上对应的键。

字体（EB Garamond / Noto Serif SC / Courier Prime）自托管在 `web/public/fonts/`，共 6MB、119 个 unicode 子集文件。**它们被刻意排除在预缓存之外**——浏览器只会下载页面真正用到的子集（实际几百 KB），下载过的会被 Service Worker 永久缓存。

### 地标水印

设计稿引用的地标水印图不在导出包里（原设计那个路径本来就是 404）。现在用的是 11 张手绘插画，源图在 `design/wm/src/`，由脚本提取成水印：

```bash
python3 design/wm/extract.py
```

脚本做四件事：按空白列/行把宫格图切成 5×2；识别并丢掉每格底部的中文标注（标注是一条又矮又靠下的独立内容带）；取亮度反相当墨量、把浅色填充压到阈值以下抹掉，再染成正文的暗红 `#5c1a22`；存成 **PNG8 调色板图**——调色板 256 格全填同一个颜色，透明度靠 `tRNS` 表逐格给出，每像素 1 字节而不是 RGBA 的 4 字节，体积省三分之一而肉眼无差别。

阈值可调：`--floor` 控制抹掉多少浅色填充，`--gamma` 控制细线实不实。脚本还会输出 `design/wm/contact-sheet.png`，按实际的 13% 不透明度叠在纸色上，改完参数直接看效果，不用启服务器。

水印分布：封面和结语页**不放**——封面本身是整版设计，结语是全书收尾，留白更像护照的最后一页。其余每页都有：8 个关卡各自在 `server/src/config.js` 里用 `landmarkKey` 指定，剩下 3 张（大教堂、大学、威灵顿）分给欢迎页、导航页、资料页、恩典站和两个浮层。页数比图多，重复是有意的——`guide` 和 `board` 是浮层，不会和正文页同屏出现。

这 11 张合计约 260KB，和字体一样**被刻意排除在预缓存之外**（`vite.config.js` 里的 `globIgnores`），改走运行时 `CacheFirst`。理由是 Service Worker 的安装是原子的：弱网下装不完就整个离线能力都没有，而水印只是页面底纹，加载不到不影响任何功能。核心 App 保持小而必装，水印看过一次就存下来。

设计稿原本还有一层放射状底纹（`guilloche`），和地标水印叠在一起太花，已在 bookVals 里关掉（`guilloche: 0`）；页脚的地标名称文字也去掉了，水印本身已经足够表达。

## 八、常见问题

**扫不出二维码？** 让选手把屏幕亮度调到最高。还不行就直接报编号——工作人员端的「输码」标签页永远可用，纯数字键盘，输 `7` 或 `07` 都能找到 7 号。

**选手忘了密码？（重要：别让他重新报名）** 管理员在总控台的「手动勾选分配」里勾中这个人，点「🔑 重置密码为 3927」，然后告诉他「你的密码是 3927，用你的编号找回」。密码是固定值，现场口头说一句就行，不用念随机数。重置会让原密码立即失效，并顺带解除他之前试错造成的锁定。

**为什么不能让他重新报名？** 重新报名会多出一个空号，他之前闯关拿的分数全留在旧号上，排行榜也会出现两个同名的人。所以报名时做了拦截：填的名字如果已经存在，会弹出提醒「已经有人用这个名字报名了（03 号）」，给两个选择——「那是我，去找回护照」或「不是我，我是另一个小明」（50 个人里出现两个同名很正常，所以不是硬拦）。总控台还有一个「⚠️ 疑似重复报名」区块，列出所有同名的号并标出哪个是空号，方便同工核对。

**选手清了缓存 / 换了手机？** 首页点「已经报过名？用编号找回护照」，输入编号 + 4 位密码即可。忘了密码就找 Reception：工作人员扫到这个人时界面上直接显示他的密码，导出的 CSV 里也有一列。连错 5 次会锁 60 秒。

**页面滚不动 / 内容显示不全？** 已修复。导入护照册设计稿时，它自带的 `html,body{overflow:hidden}` 全局规则泄漏到了整个 app，导致所有超过一屏的页面都滚不动。现在这条规则只在护照册打开时生效（`.book-locked`），离开就解除。

**总控台在电脑上看很窄？** 900px 以上宽度会自动排成两列、1280px 以上三列，手机仍是单列。

**按钮点了完全没反应？** 如果是在微信里打开的，先确认你用的是最新版本（下拉刷新一次）。旧版本用的是浏览器原生 `confirm()` 对话框，而微信内置浏览器、部分 WebView 和加到主屏的 PWA 会抑制它——此时 `confirm()` 直接返回 false，操作就静默取消了，看起来完全就是「按钮坏了」。现在所有确认都改成了应用内弹层，不再依赖原生对话框。

**总控台的分配按钮点不动 / 花名册是空的？** 大概率是这台设备的数据没同步下来（比如后台刚重置过）。「身份分配」区块会直接说明原因并给出「重新拉取花名册」按钮，点一下即可。服务端每次重置都会让数据纪元 +1，各端下次同步时会自动整份重拉。

**选手怎么知道自己被盖章了？** 护照本来就在实时同步（socket 推送 + 30 秒轮询），盖了章会自己出现。想立刻确认的话，在还没盖章的签证页上点一下中间就会主动查一次，期间显示很轻的「CHECKING 查询中…」。页面上**不留任何常驻标识**，已盖章的页面点了也不发请求，同一页两次查询之间至少隔 3 秒——防止有人站在关卡前反复戳。

**分数记错了？** 每站只能记一次。管理员登录后在选手页面用「手动调分」追加一条修正记录（原记录保留，可追溯）。

**摄像头打不开？** 确认访问的是 `https://` 地址。iOS Safari 在 http 下不会给摄像头权限，且没有任何开关可以绕过。

**要重新演练一遍？** 总控台底部「重置游戏数据」，输入 RESET 确认，可选择保留或清空选手名单。重置前会自动备份。
